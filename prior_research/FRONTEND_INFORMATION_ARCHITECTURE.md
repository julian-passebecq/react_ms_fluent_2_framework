# Lightweight docs/showcase frontend information architecture

The frontend should document and showcase the library, not become the authoring engine.

## Recommended top-level navigation

1. **Gallery**
   - all live examples;
   - filters by Cloud / Data model / Lineage / SQL / DAX / Pipeline / Algorithms / ML.
2. **Generators**
   - Cloud diagram;
   - Data model;
   - Lineage;
   - Storyboard;
   - Cheat sheet.
3. **Concept Atlas**
   - current broad taxonomy with LIVE / PLANNED truthfulness.
4. **Themes & Export**
   - professional;
   - Microsoft-modern;
   - editorial;
   - presentation;
   - handwritten;
   - monochrome.
5. **AI Authoring**
   - starter prompts;
   - JSON/YAML examples;
   - schema links;
   - copy buttons.
6. **Architecture / About**
   - D3 core;
   - React shell;
   - Python adapter;
   - roadmap and limitations.

## Homepage recommendation

Keep it much simpler than the current full catalogue:

- one short positioning sentence;
- three hero examples: cloud architecture, moving SQL/data transformation, star schema/lineage;
- small statistics strip;
- generator-family cards;
- recent/live examples;
- link to GitHub.

This is enough for LinkedIn/GitHub proof without requiring an editor.
