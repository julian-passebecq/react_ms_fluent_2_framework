# Remaining data-platform gaps

This pass adds no renderer family. It makes bounded teaching examples portable and strengthens the existing lineage contract. These limits remain explicit rather than being hidden with bespoke drawings.

| Area | Supported now | Remaining limit / disposition |
| --- | --- | --- |
| Star / semantic models | Fact grain, field roles, one fact FK → one dimension PK, declared many-to-one and filter direction | Composite relationships, many-to-many bridges, inactive/role-playing relationships, snowflakes and BI-engine ambiguity rules need a later semantic design. Metadata alone does not validate them. No database data is checked for uniqueness or referential integrity. |
| Physical star shape | Shared layered fact/dimension cards and explicit links | No centered ERD/crow's-foot or table-specific drawing engine. A star schema need not use radial geometry to communicate its semantics. |
| SQL/dbt/DAX | Hand-authored expressions, derivation labels and exact field endpoints | No parser, source-code inference, query execution, dialect/type checking, measure evaluation or upstream service discovery. Incorrect SQL text can remain structurally valid. |
| Lineage cycles | Opt-in rejection on exact derivation endpoint graph; safe deep-chain validation | Default remains permissive for compatibility. Asset and field endpoints are distinct. Mixed-granularity containment, temporal/in-place lineage and model filter ambiguity are not inferred. Explicit versioned assets are the authoring pattern. |
| Dense lineage layout | Shared layered ordering, field-height cards, short horizontal chains and long vertical chains | No arbitrary collision-free edge-label routing, bundling or graph virtualization. Very wide graphs can become unreadable when fitted to the existing Figure surface; use bounded vertical views or sibling Figures. Long labels keep full accessible names but may truncate visually. |
| Cross-cutting architecture context | Operate/Govern nodes, explicit applies-to metadata and two representative context links | Existing graph grammar does not draw spanning responsibility planes. Keep the accompanying prose; do not claim the context links enumerate every relationship. |
| Provider lenses | Same semantic IDs with conceptual/Fabric/Databricks/GCP/Azure vocabulary | Illustrative responsibilities, not product equivalence, exhaustive infrastructure inventories, reference deployment architectures, pricing or configuration. No provider runtime calls or vendor image URLs. |
| DAG execution | Existing authored retry/backfill/fan-out/fan-in trace and separate topology | No readiness engine, retry scheduler, mapped-task expansion, dependency-aware execution, backend or Spark/Jupyter runtime. Workflow FigurePlayer uses the first declared run; multiple-run navigation remains consumer work. |
| KPI/report visuals | Source → modeled field → semantic measure → visual-binding lineage metadata | Analytical charts/KPI widgets remain consumer/VizForge responsibilities. The accepted generic external Figure seam is unchanged. |
| Authoring schemas | Existing Figure envelope and Diagram structural assistance plus authoritative runtime validators | No new schema for the optional lineage semantics. TypeScript and `validateLineageSpec` are the source of truth. Figure-envelope validation alone does not certify a payload. |

The framework's seven applications, separate legacy application, existing imports, EN/NO infrastructure and private-overlay rules remain intact. New examples use English labels and the existing LocalizedText contract; a full Norwegian translation of the new teaching prose is not claimed. Browser evidence covers Chrome at 1440px and 390px, not every browser or arbitrary enterprise graph size.
