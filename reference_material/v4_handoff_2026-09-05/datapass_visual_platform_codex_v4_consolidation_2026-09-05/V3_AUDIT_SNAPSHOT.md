# V3 audit snapshot

## What is already strong

V3 is now a real reusable platform, not a set of copied applications.

Verified V3 characteristics:

- 7 application entry points share the same workspace packages.
- 323 practice items / 500 variants are imported deterministically.
- 30 semantic learning figures are reused across Algorithm Atlas, Formation and coding consumers.
- Architecture Atlas and Pilot Center share the same DiagramSpec and deterministic radial/layered layout infrastructure.
- Code Sandbox and Code Interview share challenge/progress/editor semantics but retain separate product identities.
- Visual Sandbox edits the same Figure contracts used by production consumers.
- Monaco is centralized and lazy; consumer entry routes do not load it unnecessarily.
- Public-output privacy scanning covers source maps.
- Final V3 local gate: 262 unit tests, 40/40 browser tests, package coverage floors, Storybook, all consumer builds, legacy regression, scaffold proofs and privacy checks.
- Final hosted V3 workflow on commit `36c01d4...` is green.

## What is still visibly weak

The architecture is stronger than the current visual polish.

Main observed issues:

1. Consumer surfaces still leak developer/audit vocabulary such as schema versions, source IDs, no-execution disclaimers and migration/provenance details.
2. Formation still contains user-visible historical `Dubreu` wording in original fixture/notebook text and some internal identifiers/hooks retain the old name.
3. The visual palette is correct — warm neutral, navy, muted teal, sparse amber — but many screens still feel like stacked white enterprise cards rather than the more refined Fluent/editorial reference spirit.
4. Some Figure canvases are larger than their teaching content and therefore feel sparse.
5. Algorithm Atlas explains concepts correctly but does not yet strongly synchronize code, data and state.
6. Architecture Atlas has strong semantics but its nodes still look closer to a topology editor than a polished cloud-learning diagram.
7. Pilot Project Galaxy works but needs stronger hierarchy, grouping and status semantics.
8. Code Sandbox's biggest differentiator — visual explanation — should be more obvious when a challenge has a Figure.
9. Code Interview is functionally distinct but still visually resembles a questionnaire in parts.
10. Seven consumers now provide enough evidence to perform a real duplication/factorisation audit; do not pre-emptively create wrappers without evidence.

## V4 principle

Do not chase a higher feature count. Raise coherence, clarity, presentation quality and authoring efficiency.
